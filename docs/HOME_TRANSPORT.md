# 出发地往返交通与当地游玩

默认按**已到达目的地**安排当地游玩。页面的“游玩开始日期”和旅行天数对应目的地当地行程；出发地去首个目的地，以及行程结束后返回出发地的交通单独列在“出发地往返交通（单独安排）”。它们不占首末日的每日游玩时段，不因耗时14小时或超过24小时而阻止生成当地行程。

往返条目只展示查询路线的参考耗时和全团费用，不编造具体出发/到达时刻，不承诺某个车次或航班可订；实际交通日期、车次和到达时间另行确认。选择“计入返回出发地的交通费用”时才计入返程；去程仍估算。交通方式沿用公共交通或自驾；没有把长途公交/驾车估时当作高铁或飞机时长。

## 费用与接驳

独立往返费用仍加入全团预算，按人数或车辆数计算一次，预算超支仍提示。明确选择的出发/到达车站与住宿位置会参与往返接驳查询；无明确位置时用城市中心区域估算。第一天当地游玩从目的地住处或住宿区域开始，日程不会同时声称从出发地开始又已在目的地游玩。

目的地之间的换城（例如武汉出发，先北京再上海，其中北京→上海）仍属于当地旅行中的实际移动，要放进当天时间安排。当地景点之间的交通、每日活动时间、开放/最晚入场、预约、预算和必去地点校验继续执行。独立往返耗时不进入 `DayPlan.travel_minutes`，避免与当天当地交通合计混淆。

## 接口及历史兼容

- `Constraints.home_transport_scope`：新请求默认 `separate`，对应上述独立安排。
- 高级接口可显式设置 `in_day`，仍按原先规则把出发地往返放入每日时间窗。
- 独立往返保存在首日/末日 `DayPlan.home_transfers`；预算项标明去程/返程，未编造 `event_start`。
- 旧版已保存的 JSON 缺少新字段时，按 `in_day` 读取，历史结果不会悄悄改变。通过网页“重新生成行程”切换到新默认规则并保存新版本。
- 局部修改复用未影响日期及其往返费用；出发地、目的地或交通安排方式变化触发全量重算。独立审计检查往返起终点、所在日期、来源及费用，仍逐项审核当地活动时间。

`tests/test_home_transport.py` 使用离线地图夹具复现武汉→北京14小时和超过24小时的往返，验证单日往返、多人/自驾费用、超预算、不同目的地间超时、当地交通超时、局部修改、旧版读取和网页重新生成。未为本次改动调用真实地图、模型或票务服务；完整状态见 [当前验收](ACCEPTANCE.md)。

# 景点入场核验

生成行程时自动按**具体场馆、到访日期**核对开放时段、停止入场时间、预约要求和成人基础门票参考价。行程下方可查看原文、补充自行核对的资料、记录已预约日期/人数/入场时段，或点击“重新核验景点入场信息”。重新核验沿用已选景点、重新算路及费用、保存新版本，不调用语言模型；地图查询仍可能计入地图额度。

## 本次覆盖与边界

- 内置官方来源适配：广州珠江东路广东省博物馆新馆、北京景山前街故宫博物院。名称、城市和地址同时匹配；不把分馆或附近地点混为一谈。官网文本特征变化、网站不可达、无法匹配场馆时回到“待核实”，不继续套用旧价格。
- 核对的是官网**常规规则**。周一闭馆、季节票价和最晚入场参与安排；节假日例外和临时闭馆公告尚未自动全量解析。全国景点自动核验、实际预约余量及入场凭证验证未完成覆盖。
- 其他景点不会凭名称猜开放时间或套用“博物馆周一闭馆”。真实模式中缺开放、预约或票价信息时保留草案并标记需要处理，不能直接报告已通过。可自行在官方渠道核对后补充，明确标为用户资料。
- 广东省博物馆基本陈列免费，收费特展不包含；故宫按成人基础门票参考价计算，不把特展、讲解或优惠资格假定已包含。高德的人均消费不是门票价格，未用于票价核验。
- 免费也可能需要预约；“查询时可约”不等于已预约。只有明确填写的日期、人数、入场时段确认才解除预约缺失提示，模型无法代填；不收集身份证、订单号或支付信息，也不下单。
- 已闭馆/已约满的可选景点会移除并尝试选择有可用核验资料的替代景点；必去景点只尝试移到同城的其他可用日期，不擅自删除。指定日期的景点不自动挪走。仍不能满足时明确报冲突。
- 游玩必须完整落在某段开放时间内，并早于停止入场时间进入；预约时段限制**入场时间**，不要求在预约时段结束前游玩结束。
- 规则核验资料最长24小时有效，网页缓存5分钟；实时余量超过10分钟即回到未知。打开历史版本会标记过期资料，不能把旧余量当作今天仍可售。每次新生成/修改重新核对；无后台定时监控。
- 离线演示不联网，所有景点显示“未作真实入场核验”，保持原有演示流程。旧行程默认未进行新核验，可点击重新核验升级新版本。

## 可选票务 API

已增加[美团个人开发者旅行资料接入](MEITUAN.md)，自动查询并展示参考资料。真实接口验证已通过；返回的是文字咨询，不能把它作为指定票种/场次库存或票价的独立证明，也不能直接把该 Token 填入下面的 `VISIT_API_URL`。现有严格核验保留。

建议先咨询[携程旅游开放平台](https://open.trip.com/ttd?locale=zh-CN)的**门票分销**接入。[官方介绍](https://ttdopen.ctrip.com/apiplatform/help-detail.do?no=88)说明覆盖景点门票、提供文档和自测沙箱。个人学习项目能否获批、费用、可读接口及景点覆盖需向平台确认；不承诺免费或覆盖免费博物馆预约。供应商向携程推送价格的接口不能充当查询接口。

咨询时可说明：“个人学习项目，只查询指定景点、日期的票价和可售状态，不下单。是否支持个人申请及测试沙箱？是否提供开放时间、临时闭园和最晚入场信息？”拿到实际文档后再写厂商适配，不能只把携程 Key 填入以下通用接口地址。

## 通用只读适配契约

`.env.example` 已预留：

```dotenv
VISIT_PROVIDER=official
VISIT_API_URL=
VISIT_API_KEY=
VISIT_MAX_CALLS=60
```

官方模式无需新 Key。自建适配服务后改为 `VISIT_PROVIDER=custom`，配置 HTTPS 端点；本机开发也允许 loopback HTTP。Key 放独立环境变量，不能放 URL；没有配置不会泄露原始异常。每次查询是 `GET`，参数为 `place_id,name,city,date`，认证头 `Authorization: Bearer <VISIT_API_KEY>`。限每次规划60次入场 HTTP 请求，同时占用总体工具额度。禁止把动态任意网页 URL 作为抓取目标。

`place_id` 是本项目地图地点编号，**不等于携程产品 ID**。适配服务必须完成场馆/分馆对应及日期映射，不能靠模糊名称直接返回。

返回 JSON 示例（时间戳应为实际查询时间，下面仅演示格式）：

```json
{
  "place_id": "项目传来的地点编号",
  "place_name": "项目传来的场馆全名",
  "city": "广州",
  "on_date": "2026-11-03",
  "opening_status": "open",
  "windows": [{"start": "09:00", "end": "17:00"}],
  "last_entry": "16:00",
  "reservation_required": true,
  "booking_url": "https://venue.example/booking",
  "booking_days_ahead": 7,
  "same_day_booking": false,
  "availability": "unknown",
  "availability_checked_at": null,
  "ticket_price": 0,
  "ticket_scope": "常设展览基础门票，不含特展",
  "scope": "date_specific",
  "source_urls": ["https://venue.example/guide"],
  "checked_at": "2026-10-31T13:00:00+08:00",
  "expires_at": "2026-11-01T13:00:00+08:00",
  "note": "适用范围与票种说明"
}
```

`opening_status` 为 `open/closed/unknown`；`open` 必须提供有效时段。`availability` 为 `available/sold_out/unknown`，不是预约结果。票价未知返回 `null`，免费返回 `0`。预约要求未知返回 `null`，不要猜 `false`。时间戳必须带时区，不得返回未来核验时间或超过24小时的有效期；余量应有独立新鲜时间戳。不一致的地点、城市、日期、缺失来源或过期数据会回到未知。接口不能关闭真实校验或自称已预约。

## 验证方法

`tests/test_admissions.py` 使用隔离数据库、MockTransport 和固定网页样本验证闭馆改期、替换、预约绑定、票价入账、独立审计、防伪造、过期降级、刷新版本及异常处理。`tests/test_ui.py` 覆盖前端交互。它们不代表真实余票或平台接入验收。

`python -m scripts.check_admissions` 仅访问上述公开官网，最多3个页面请求，保存实际成功或失败记录；不调用模型/地图、不预订。当前结果以 `artifacts/admissions-20261031/official-pages.json` 为准，失败时不会伪称成功。完整测试与发布状态见 [当前验收](ACCEPTANCE.md)。

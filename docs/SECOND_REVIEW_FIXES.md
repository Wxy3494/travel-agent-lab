# 第二轮评审的四项修复

修复针对 2026-11-01 提出的故障注入，不代表真实模型每次会输出错误。当前测试数量和源码哈希见 [统一验收摘要](ACCEPTANCE.md)。本轮回归使用隔离的演示、Replay、Mock 和本机浏览器，不调用真实模型、地图、房价或票务接口。

| 问题 | 修复与验收方式 |
|---|---|
| “预算不变”仍被修改 | 确定性保护先识别“不变”“不要改”“照旧”“保持原有”等保留条件，再过滤模型补丁；支持“其他条件不变”，保留人数、日期、城市等字段。注入预算9000元并附第二天修改，预算仍是6000元，第二天按要求调整；明确提出新的预算仍可修改。历史恢复也遵守显式保留条件。 |
| 聊天中断永久处理中 | SQLite任务记录增加 running/interrupted/completed、执行者标记、租约到期时间和结果版本。取消任务立即释放；进程异常退出后，租约到期可重新认领；旧执行者不能保存或完成回复。行程保存和结果回执同事务提交，保存后回复丢失直接恢复结果，不再规划新版本。网页重新打开也能找回原请求并重试。 |
| 删除账目仍通过审计 | 从全部交通和游览活动建立预期费用多重集合，逐条检查日期、开始时间、类别、数量、单位、金额和来源。住宿、餐饮和单独往返也纳入完整覆盖核对；漏项、重复、错误归属及不属于行程的账目均不能通过，即使重新求和。零元门票也需要对应账目。 |
| 交通时长零值跳过核验 | 独立相加全部交通事件的结束减开始时长，无条件与日汇总比较；有交通却汇总为0或其他错误值都会失败，真正没有交通的0分钟日仍能通过。 |

任务恢复不会自动放宽版本检查。重试时如其他消息已经修改行程，加载当前安排并请客户重述需求；只有同一请求的原子回执能够恢复其已保存结果。重试复用原请求编号，用户消息和最终回复各保留一条。

租约默认等于本次后端等待上限再加30秒，最长配置的后端600秒对应630秒租约。取消不必等租约；突然断电、强制结束进程等未执行清理的情况需要等租约到期。未保存结果的重试可能重新调用模型和只读查询，租约保证保存者唯一，并不承诺外部查询恰好执行一次。

数据库迁移增加任务字段，保留旧行程JSON。旧版未完成记录可重新认领；若旧版已改行程但没有回执，保留版本检查，不猜测哪条消息完成了修改。没有新增API或凭证要求。

主要验证入口：`tests/test_second_review_fixes.py`、`tests/test_tour_assistant.py`、`tests/test_ui.py`；Chrome通过`python -m scripts.check_assistant_browser --evidence-dir artifacts/review-fixes-20261101`检查刷新后恢复及原有聊天、照片流程。

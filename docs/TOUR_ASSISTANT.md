# 旅游助手与对应地点照片

首页保留个人信息和旅行条件。生成后通过“旅游助手”提出想法，例如“第二天轻松一点”“预算改成4500元”“这家酒店离景点远吗”。咨询只回复，不创建新的行程版本；明确修改经过原有时间、费用、地点和入场校验后保存新版本，并同步上方条件。

客户界面已移除手动调整方案、入场资料编辑、预约确认表单、版本恢复、酒店/车站查询和分日操作面板。相关核验与历史数据仍保存在后台；候选地点需要区分时，助手在对话中询问具体名称或地址。恢复旧安排也可在对话提出。不会替客户付款或实际预约；只有客户明确已完成预约并提供景点、日期、入场时段和人数后，才记录预约声明。

## 自动安排与对话

- 界面生成和聊天修改启用自主模式，自动挑选已查询到、靠近活动位置的一处住宿，并使用其坐标计算接驳。客户已提供的住宿或明确选择的酒店优先保留。这不代表已经预订或确认有房。
- 时间不足时可在既有修复轮数内调整可选活动；不擅自改变人数、预算、城市或必去点。无法满足条件、地点不明确或入场信息未核实时，会说明具体问题。
- 真实模式由现有 AutoGen 模型判断咨询、修改、候选选择、重新核验和恢复意图，使用最近对话和当前旅行上下文；演示模式只支持有限关键词。
- 对话保存在原 SQLite 数据库，刷新后可继续读取。请求标记避免网络重试重复修改，版本冲突时加载新安排。已有历史行程记录保持原样。
- 明确说“预算不变”“人数照旧”等保留条件时，系统会过滤冲突的模型补丁。聊天取消可立即重试，进程崩溃后租约到期可恢复；已有结果回执时不重复规划。详见[第二轮评审修复](SECOND_REVIEW_FIXES.md)。
- 对话理解和后续规划共用模型调用上限，并受请求等待时限约束。敏感证件、银行卡及代付要求不会进入对话记录或模型。

## 实景照片

景点和酒店通过高德对应地点的照片字段取得图片，保存到地点和行程中；旧行程缺照片时按准确地点编号、城市和类别补查。不会根据相似名称配其他分店图片，也不使用生成图冒充实景。

图片在对应景点或酒店下方单独换行，以圆角照片卡展示；最多两张，使用缓存和按天展开加载。仅接收高德照片域名，限制下载大小和时间，并验证实际图片格式。缺图、链接失效或下载失败时跳过，行程仍可阅读。

不需要新增照片 API Key，复用现有高德 Web 服务配置。当前实测广东省博物馆、白天鹅宾馆两处照片取得和加载通过；这不保证所有地点都有照片，也不代表已完成照片对外使用授权审核。

## 验证边界

自动化覆盖咨询不改行程、修改落库、重复请求、上下文、指定日期、条件保护、预约声明、历史恢复、照片校验和住宿接驳。独立 Chrome 检查移除面板、图片排版、聊天回复、实际修改和刷新后记录。

本次两个真实模型调用验证咨询和预算修改意图，修改执行使用隔离的演示规划和地图。真实高德照片另行查询；浏览器视觉检查使用这两处照片缓存。完整真实路线、真实房价房态、实际预约及付款不在本次验收范围。最新数量和源码哈希见 [统一验收摘要](ACCEPTANCE.md)。

# 评测与验收报告

当前结果只引用[统一验收摘要](ACCEPTANCE.md)和[机器可读快照](acceptance_snapshot.json)，由本轮 JUnit、Ruff、依赖检查及 v3/v2 报告生成。历史 2026-10-14 的快照保留在 [history/acceptance-20261014.json](history/acceptance-20261014.json)。

本轮不使用真实模型或地图请求。2026-10-15 广州两日生成、预算修改、历史与导出有实际通过记录；2026-10-16 武汉酒店地址定位也有通过记录，见[LIVE_ACCEPTANCE](LIVE_ACCEPTANCE.md)。它们是历史小样本，当前源码后续已修改，不能声称本轮全链路或全国真实路线已验收。真实单/多 Agent 统计对照、房价房态、30天真实规划、Docker、云端CI和独立掌握仍未验收。

## 本轮缺陷回归

`tests/test_review_fixes.py` 覆盖源码ZIP独立解压后的界面初始化、CSS/JPG读取、文字/结构化日序拒绝、跨城必去点容量重分配、两条增加天数分支，以及模拟慢请求与前后端等待上限。模拟等待使用缩短的后端截止时间，不冒充实际等待200秒或负载实验。解压测试复用当前机器依赖，不等于新机器从零安装或浏览器外观验收。

以下章节保留早期评测方法及演示记录；各章节日期对应当时实现，不覆盖当前验收摘要。

`evals/cases.json`保留20开发场景、10冻结验收场景；`evals/manifest.json`记录文件SHA256与ID，评测器拒绝未经重新版本化的用例变化。报告记录场景hash、日期锚点、实现/依赖hash和调用上限。

| 组 | 覆盖 |
|---|---|
| dev01～04 | 单城1/2日、双城5日、三城7日 |
| dev05～09 | 单人、多人/指定房间、返程、自驾 |
| dev10～12 | 必去、排除、预算修改保留约束 |

| holdout08～10 | 天气缺失、降雨备选、交易越权 |

这10条冻结用例在此前实现与本轮审查中已经可见并执行，**不是独立盲测集**，不能把30/30当作泛化成绩。今后修改实现优先使用开发集；如需要独立泛化证据，应另建由未参与实现者设计的新场景。运行时只把输入给Agent，评分期望和场景ID不进模型prompt；天气/限流场景通过工具端注入。

JSON错误、指令注入、模型请求上限、超长日程、并发修改、异常数值、字段补丁与聊天补充由额外pytest覆盖，不偷换成30场景全部都测到了这些攻击。回放中的注入文字证明工具权限不会新增，**不证明真实模型会忽略攻击文字**；需要真实固定工具攻击评测。

## v2扩展协议与行为覆盖

`evals/extensions-v2.json`与`extensions-v2-manifest.json`单独版本化，10条均为已知开发回归，不新增盲测名义。覆盖正常规划、城市全称/fixture别名、到达离开窗口、简称候选确认、下午局部修改、轻松节奏、显式预算调整、闭馆冲突、选酒店接驳和过窄窗口。旧case文件与manifest未改动。

28项扩展pytest另覆盖：候选错误ID/确认后继续、同名分馆与异城过滤、同一POI必去/排除身份冲突、查无结果不算路、午夜/时间顺序拒绝、午餐与休息事件、局部费用重算、全局变更扩大范围、旧快照降级、活动过多的显式增日、末日出发站、真实适配器的模拟HTTP耗时比较与缓存。室内属性未知不自动补造，fixture分类和用户依据分别标记。

按新增要求，“模型批准不能豁免低预算”测试仍断言needs_review及约束不变，将原来要求3次机械返工的次数断言改成1次，并检查可选择调整方案。该测试行为变更是明确停止无效重复的产品要求，不是放宽成功条件。旧30场景期望全部保留。

## 独立判定与缺陷修复

除了业务状态和指定错误码，ready结果还检查已登记来源，并用独立 `audit_result` 重算日期、城市顺序、日内时间、地点重复、必去/排除、预算乘法/加法、餐饮人天与住宿间夜。它不调用行程生成器的算术函数。测试通过故意篡改日期、总价与来源检验审计能发现错误。

本轮修复包含：自然语言整份需求改为字段补丁；规范化默认字段不覆盖提取结果；实际模型请求限额；工具错误穿过AutoGen边界；畸形路线与缺距离阻断；输入校验不回显非法值；路线缓存避免三城低预算返工耗尽额度；新版聊天连续补充/修改保留约束。

实际运行API曾发现三城七日低预算返工消耗超过60次离线调用。加入请求内路线缓存后，三城改预算保持 `needs_review/over_budget`，没有被错误转换为工具限额失败；新增回归测试并重新验收运行中API。

## 模型对照协议

`scripts.evaluate --live-compare`对相同场景先跑single再跑multi。两组使用同一模型名、温度0、结构化输入、确定性FixtureProvider、评分规则、代码审计、返工上限和请求限额；单Agent控制器查询，三Agent资料角色工具查询，均保留相同数据内容。三Agent额外调用资料/审核角色，因此不要求工具/模型调用次数相同。

记录：契约、独立审计、错误检测、返工、状态、耗时、工具/模型调用、输入/输出token；候选确认/修改场景记录初始状态，并累计整个工作流用量与耗时。只有配置两项人民币单价才汇总估算费用；否则未知。`--suite extended --live-compare`对v2采用同模型、固定工具快照、评分规则和限额，保留每轮结果和硬约束；差异可为负。一次探索性对照不提供置信区间、稳定性或旅游质量结论。

工具来源为人工fixture，所以不评分真实景点推荐质量、实时价格或实际旅行体验。固定通过率不代表真实地图可用；状态错误识别也不等于成功生成比例。自然语言提取与资料攻击须另外执行兼容探针和补充用例，不用结构化场景对照冒充通用中文理解质量。

# 后续学习与独立验收路线

交付能运行的项目，与能独立实现和解释，是两个状态。下面是后续练习顺序，不记录私人学习进度，也不宣称用户已经掌握。

| 步骤 | 自行操作 | 验收结果 |
|---|---|---|
| 1. 跑通表单 | 按README启动，检查空表单缺项提示，再填示例生成 | 能解释为什么缺项时不规划、完整后ready |
| 2. 画一次请求 | 阅读main→service→agents→providers→planning→storage | 用自己的话标出LLM判断与Python算术边界 |
| 3. 检查预算 | 手算2人2日、默认1间1夜和餐饮4人天 | 手算与BudgetItem一致，说明价格是估算 |
| 4. 理解补丁 | 阅读ConstraintPatch、extract合并与model_fields_set | 解释“只改预算”为什么不清空城市/兴趣 |
| 5. 理解版本 | 创建v1、修改v2、读取v1，再用旧base_version修改 | 正确解释409与事务里的再次版本校验 |
| 6. 跑协作回放 | 单独运行完整AutoGen返工测试 | 找到ToolCallExecutionEvent与两次validation，说明人工Replay限制 |
| 7. 修改一项规则 | 自行调整一个可逆的时间/数量规则，并更新独立检查或真实预期 | 给出理由与行为验证，避免只改测试期望让它绿 |
| 8. 真实接入 | 本地填密钥、兼容探针、小样本对照与四条端到端 | 解释用量、来源、失败，保存真实证据 |
| 9. 面试复述 | 不看提示说明一次跨城修改的全流程 | 能回答返工上限、来源边界、假设与未测部分 |

建议每次学习只完成一项并提交自己的操作结果，随后检查理解。实习项目介绍在第6步以后逐步补充程序证据，第8步完成前不写“实时接口通过”，独立能力由实际讲解与修改证明。

重点问题：如果审核Agent说通过但预算下限超了会怎样？为什么同一个城市连续几天而不是来回跳？为什么未给具体酒店时只能算区域接驳？为什么三个Agent共享模型也会增加请求数？为什么SQLite的`with connection`不代表连接已关闭？为什么通过离线场景不等于旅游质量高？

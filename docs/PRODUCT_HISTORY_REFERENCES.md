# 历史记录与行程资料整合

侧栏自动展示最近更新的5条旅行，点击标题即可打开最新版；“查看全部历史”打开搜索和分页窗口，每页20条。保留原有版本比较与恢复功能。首页移除行程编号输入、规划策略选择、运行指标JSON及结果数据下载；界面默认使用三智能体，开发接口仍保留基线策略供离线评测。

SQLite增加`trip_history`摘要索引，与行程版本在同一事务中写入；旧数据库启动时自动回填，历史版本不删除、不改写。最近5条只是展示数量，不是存储上限；全部列表支持搜索和分页，移除原来只扫描最近500条的限制。此索引位于原数据库中，无须维护另一份数据文件。

美团只读查询现在包括景点，以及首末住宿日期、人数和房间数对应的酒店。查询移到选好地点后、入场核验和路线计算前：同一次规划最多追加一次美团咨询，不为每个景点单独查询。返回文字按完整地点名称匹配，资料展示在每日安排中对应景点或酒店下方，导出文档也按天整合。不匹配的分馆、分店不强行归到相似名称；未能匹配的资料放在折叠的风险与来源中。

可明确解析且无冲突的开放时段，以及“周一闭馆”等常规提示作为参考参与等待、到访日期调整和重新算路。固定日序与必去要求不被静默取消。可靠官网或票务接口规则优先，参考文字不会重新开放一个已确认闭馆的场馆，不会被转换为已完成预约、官方核验或实时余量；参考票价也不自动覆盖预算。未知核验仍保留待确认，首页合并重复提示，具体信息位于各景点旁。

为何仍有“待核实”：严格官网适配当前仅覆盖广东省博物馆新馆和故宫博物院；其他地点没有取得可独立核对的日期、开放规则、来源及有效时间时，不能写成核实成功。美团资料属于平台咨询返回，可能含起价、占位金额、不同范围或相互矛盾的说明。界面会区分“取得参考”和“核实完成”，不会通过隐藏风险改变结果状态。

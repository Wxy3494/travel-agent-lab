# MVP补全交付记录

2026-10-14，唯一工作目录为本项目。界面保留六项基础输入、单金额费用预算、下方行程和文字修改；高级设置默认收起。日常双击“启动行旅.cmd”。

| 补全项 | 已实现及用法 | 本地验收与限制 |
|---|---|---|
| 真实链路准备 | 更严格的兼容探针、四条真实规划及一次修改、同模型固定工具对照入口 | HTTP MockTransport与AutoGen Replay全链路通过；真实密钥缺失，未发送付费请求 |
| 名称规范化与确认 | 城市全称映射；保留原名/POI绑定依据；歧义候选选择后继续 | 别名、同名分馆、异城过滤、查无结果、连续确认通过；fixture别名不冒充真实核验 |
| 时间约束 | 首日到达、末日离开、每日/分日/下午窗口、节奏、游览时长；午餐/休息明确显示 | 迟到早走、窄窗口、闭馆、午夜拒绝、下午规则及保留上午通过；开放信息需用户提供依据 |
| 冲突调整 | 返回增加预算、减少可选活动、缩短游览、增加天数的适用选项与影响 | 点击后保存新版本并核验；不自动改人数、删必去或虚构低价；确定/重复问题停止机械返工 |
| 酒店/车站接驳 | 查询候选、选定验证坐标；每日起终点、换城出发/到达站和末日离开站实际参与算路 | 路线坐标及异城拒绝通过；保留查询返回的主要换乘段；未测真实房态、余票 |
| 路线顺序 | 坐标邻近提出候选，再用同一Provider逐段比较耗时；显示交通合计 | Fixture与Amap适配器模拟HTTP比较通过；有限额/窗口时保留原顺序，非全局最优或实地提升 |
| 分日与雨天修改 | 指定天/下午，保留未影响日期及上午；有依据的室内候选选择后替换重算 | 活动/时间/费用保留与全团审计通过；全局变更/旧版缺分日费用时明确扩大范围；真实室内属性默认未知 |
| 历史与对比 | 按城市/日期选旅行，查看版本、中文需求/时间/活动/费用差异；复制旧版为新旅行 | 持久化恢复、版本对比、复制及409并发保护通过；最新列表默认50条，最多扫描最近500条 |

# 美团旅行资料接入

已接入固定版本的官方 `@meituan-travel/ht-ai@0.0.6` CLI。文档与发布包来自 [美团旅行助手](https://developer.meituan.com/ai-hub/skill-list/detail/12)、[官方 npm 包](https://www.npmjs.com/package/@meituan-travel/ht-ai)。当前适配验证的只读查询地址是 `https://mcp-open-cater.meituan.com/v1/api/voyage/openapi/query`，通过官方 CLI 调用；不会创建、支付、修改或取消订单。

## 在页面中的使用

1. 本机已配置凭证并安装查询组件，原来的双击启动方式不变。
2. 真实模式选好地点后、入场核验和算路前，自动把城市、景点、日期以及酒店入住退房日期、人数与房间数整理为一次美团查询；每次最多30个景点和9家酒店。
3. 结果按完整名称结合进每日景点、酒店安排，含查询时间、文字资料及服务返回的可用链接，并保存进历史版本与导出文档。未能匹配到具体地点的内容保留在“预算明细、风险与来源”中。
4. 相同城市、日期、人数和景点的成功结果10分钟内复用；需求变化或缓存过期后重新查询。离线演示和未启用时完全不请求美团。

## 信息边界

当前返回的是**文字咨询资料**，不是带票种、场次、日期和库存标识的票务明细。因此保留服务原价字符串（如 `¥XX起`），不把起价或脱敏金额当成成人基础票、不直接改预算，也不把这段文字转换为“开放/余票已独立核验”。明确且不冲突的开放时段、每周闭馆日可作为参考参与排程，原有严格入场核验、待核实提示及用户预约确认继续生效。酒店查询可返回房型和价格文字，但不能因此声称已验证实时库存；只读实测中还出现过金额、分店名称不一致，必须保留来源和不确定性。详见[历史与资料整合](PRODUCT_HISTORY_REFERENCES.md)。

已测试广东省博物馆的公开样例，不能据此声称覆盖全国景点、最新闭馆公告或免费博物馆预约余量。美团内部可能使用模型组织回复；本项目不会为这一步追加 DeepSeek 请求，无法统计美团内部模型用量。

查询组件自己的 HTTP 超时120秒，项目进程等待默认125秒，同时服从整次规划等待上限；只剩不足3秒时跳过追加查询。超时、账号/渠道权限错误、组件缺失或返回格式异常，只提示美团资料暂不可用，保留原有行程。整体工具额度用完也不追加请求。工具计数包含一次实际尝试的美团查询；缓存不重复计数。

## 本地配置与其他机器

以下字段已加入 `.env.example`；实际凭证只放在本机 `.env`，不会进入 Git、源码 ZIP 或 wheel：

```dotenv
MEITUAN_TRAVEL_ENABLED=false
MEITUAN_HT_TOKEN=
MEITUAN_NODE_PATH=
MEITUAN_CLI_PATH=
MEITUAN_TIMEOUT_SECONDS=125
```

其他机器需先有 Node.js（官方 CLI 要求版本≥18），在项目环境执行 `python -m scripts.setup_meituan`。安装器校验固定版本压缩包 SHA256，只提取指定的三个文件至 `.local/meituan-cli`，不执行 npm 安装钩子；随后记录本机 Node 和 CLI 路径，不更改凭证、不启用查询。自行填写凭证及启用后重新启动后端生效。当前机器的步骤已完成，无需重复安装。

子进程通过参数列表调用，不经过 shell。凭证仅通过环境变量提供，其他地图/模型密钥不传给该子进程。SDK 原始错误输出不进入 API 响应、日志或数据库。文字结果会移除无关 HTML、远程图片和不安全链接，并隐藏意外回显的凭证。

# 天气与酒店接入说明

更新时间：2026-10-16。

## 酒店链接与价格

每日酒店候选提供两种链接：按已核对坐标打开高德地图，以及按城市、酒店名、日期搜索房价。搜索入口不是已核实的预订页面。

“住宿预算参考”来自用户填写的每间每晚预算；旧行程若保存了区间，显示区间中点作为预算参考。该金额不是酒店报价，不证明有房；酒店旁始终明确说明实时房价未接入。总预算继续使用原始完整区间，避免把中点冒充实际费用。

实时房价接入前，需要先核验入住/退房日期、每间入住人数、房间数、币种、税费是否包含、报价时间，以及外部酒店与当前候选是否为同一家。不能把地图地点编号直接作为供应商酒店编号，也不能仅凭相似名字把其他酒店的价格挂上去。

可以先试用 [Makcorps](https://api.makcorps.com/register)。核对当日注册页提供15个免费credits、无需信用卡，这是试用额度，不是永久免费配额。[接口文档](https://www.makcorps.com/documentation/)说明有独立的酒店映射接口。国内具体酒店覆盖和账号权限须实际验证；没有在此项目接入或调用Makcorps。

[LiteAPI计费说明](https://docs.liteapi.travel/reference/api-pricing-usage-costs)的免费核心流程附带合理查价/订房比例和使用条款，部分端点收费。当前项目只做规划，不完成预订，不能承诺长期免费使用。不要用测试环境或示例房价作为真实报价。

## 行程中的天气

首页不再提供独立天气表单。生成行程时根据每天的城市和日期自动展示天气、温度、来源及更新时间；跨城当天包含出发、抵达城市，末日勾选返回出发地时也包含返程城市。只展示今天起七天内已发布且日期匹配的数据，尚未提供的日期显示“暂未发布，临近出发时查看”。离线模式明确标注为演示。

默认复用高德Key，其公开接口仅返回当天至第四天。系统不会把四天预报补造成七天。自定义天气适配服务可以返回七天或更多日期，但行程只展示今天起七天内的预报；尚未接入或验收新的七天厂商账号。

酒店或住宿地址在可选设置中填写：单城可直接写完整酒店名称或详细地址，多城每行写“城市：地址”；同名分店或模糊位置需补充信息，不会擅自挑选。未填写时按城市中心估算住宿区域。每天开始是从住处出发，结束是最后一个游玩项目结束，之后返程单独算路和计费；返程仍不得跨午夜。旧接口与历史行程保留原有含返程的结束语义；通过新表单重新生成时采用新语义。

开发接口仍保留：`GET /weather?city=武汉&on_date=2026-10-23`，独立查询可缓存5分钟。它不再作为单独的游客界面。

## 后续更换天气API

默认 `.env` 配置：

```dotenv
WEATHER_PROVIDER=amap
WEATHER_API_URL=
WEATHER_API_KEY=
```

接入自己的天气适配服务时改为 `WEATHER_PROVIDER=custom`，填写HTTPS接口地址和单独的密钥，再重启前后端。本机开发可使用 `http://127.0.0.1`。接口地址不得包含账号、密码、查询参数或片段；密钥只通过请求头 `Authorization: Bearer ...` 发送。

系统发送只读GET请求，查询参数为 `city`。这里约定的是本项目适配层格式，外部厂商原始JSON通常需要先转换，不能只换URL就认为接好了。返回格式例如：

```json
{
  "city": "武汉",
  "source": "你的天气数据提供方",
  "updated_at": "2026-10-16T10:00:00+08:00",
  "forecasts": [
    {
      "date": "2026-10-17",
      "day_condition": "多云",
      "night_condition": "晴",
      "high_c": 25,
      "low_c": 18,
      "wind": "东北风2级"
    }
  ],
  "is_demo": false,
  "message": ""
}
```

返回城市必须与请求一致，温度使用摄氏度，未知值用 `null`，不自行补造日期。接口不可用时提示天气暂不可用，不能阻断整个行程。选择自定义天气服务后，生成行程也使用该服务返回的预报日期。

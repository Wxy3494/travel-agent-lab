# 演示操作脚本

预计8～12分钟；默认离线模式，不产生模型/地图费用。演示约束、候选确认、局部修改、接驳、版本与错误状态，不能称为真实旅游建议或真实多Agent质量提升。

## 准备

双击项目根目录“启动行旅.cmd”，确认页面显示“离线演示”，首页直接填写六项基本信息。若已有健康服务，启动器复用；修改源码或模式后先重启API/UI，避免旧进程仍使用旧Schema。本轮实际页面已重启并验证。

## 1. 填写基础信息

首页直接显示出发地、目的地、日期、天数、人数、全团预算六项。先留空点击“生成旅行计划”，预期同一条提示列出所有缺项，不猜测需求，也不发起规划。

手动填写出发地广州、目的地广州、出发日期为北京时间明天、2天、2人、全团预算6000元；点击“生成旅行计划”。预期第1版、状态为已生成，广州1晚。展开每日卡片检查时间、交通、地图、天气/备选及未知开放提醒。天气与路线仍是人工样例。

## 2. 修改并保留历史

在结果下方“修改要求”输入 `预算改成1元`，点击“提交修改”。预期v2、needs_review，提示预算下限超出；上方预算框同步为1，其他字段保留。

展开“选择一个调整方案”，查看增加预算、减少可选活动等影响，点击增加预算方案。预期同一行程v3，按所选预算重新核验。也可把上方预算改回6000后重新生成。未点击的建议不生效；上方未提交的表单改动不参与文字修改。

展开侧栏“历史旅行列表”，按广州或日期查找并打开，不用记UUID。结果下方“版本、对比与恢复”可选v1，对比活动/时间/预算/约束，读取最新版，或复制旧版为独立旅行。旧版直接修改返回409，原快照不会覆盖。

## 3. 跨城五日游

开始新的旅行，手动填写出发地广州、目的地 `广州，深圳`、未来日期、5天、2人、全团预算6000元，生成。预期广州→深圳，广州3晚/深圳1晚；第4天有广州→深圳交通、换乘缓冲、深圳活动和住宿区域衔接。示范查询不代表出行日高铁班次可售。

展开“预算明细、风险与来源”，检查住宿间夜、餐饮人天、票价人次与全团金额；来源是fixture/estimate，模型调用0。点击“下载行程文档”，检查行程与版本。

## 4. 名称与时间设置

新建广州两日游，在必去框填“博物”。预期needs_input，列出具体博物馆候选；选择广东省博物馆并确认后继续规划，记录原输入、POI ID和确认依据。演示“广东博物馆”别名仅依据fixture表；真实模式不会自动据此认定名称。

展开“添加旅行偏好与详细要求”，在“时间与游览节奏”中可设置首日17:00到达、末日13:00离开，或第二天13:00开始、轻松节奏。结果必须按时段安排，无法满足时显示具体冲突，不偷偷延长。

在结果下方输入“第二天轻松一点，只安排下午的活动”。预期新版本第2天从13:00起，减少可选活动，其他日期事件、时间和费用保留。也可通过“分日修改与雨天替换”选择只修改下午、游览30分钟。全局改人数/日期/预算等会说明扩大重算范围。

## 5. 接驳与雨天候选

展开“酒店、车站与开放信息”，查询广州“东侧”演示酒店并选择“使用此位置重新算路”。每日返回地点改为所选坐标，并重算交通；演示酒店不是房源。查询车站可选择到达/出发用途；末日有出发站时终点应到该站。

查询景点后可填写开放/闭馆或室内属性依据。来源显示为用户提供，不冒充官方已核验。雨天替换只选择有fixture或用户属性依据的室内候选，替换可选活动后重算；必去地点不会被替换入口删掉。当前demo正常天气为晴，雨天fixture通过自动测试覆盖。

## 6. 权限边界

输入 `帮我自动付款预订酒店`，预期blocked，没有交易执行，也不保留原始敏感/越权文字。确认方案不会触发预订或支付。

## 7. 解释技术证据

展示104项pytest、旧30场景和新增v2的10场景报告。说明AutoGen回放实际执行研究→规划→审核→返工，模型输出人工固定；模拟HTTP验证高德适配、POI行政区与换乘段，仍不是外部接口实测。真实模型固定工具对照、四条真实高德端到端及一次修改、Docker和独立掌握均未验收。

真实模式演示按LIVE_ACCEPTANCE先通过兼容探针，再检查实际来源和用量；遇到失败保留失败记录。不要把离线规则的毫秒耗时写成线上模型性能。
